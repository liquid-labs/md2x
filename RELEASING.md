# Releasing md2x

This is the release procedure for `@liquid-labs/md2x`. Agents are the primary audience (Flow's release skills read it by fixed name); human operators are the secondary audience and can follow the same steps by hand. Steps marked **user-run** must be performed by a person in their own terminal.

## Manifests

- `package.json` (`version` field) — primary
- `package-lock.json` (`version` and `packages[""].version` fields)

Versions are prerelease-style (`1.0.0-alpha.N`). The bump tool below updates both manifests.

## Bump tool

`npm version <new_version>` (creates the version commit and the `v<new_version>` tag). The `preversion` script runs `make all && make qa` first and aborts the bump if the build, tests, or lint fail. Do not bypass it.

## Changelog

`CHANGELOG.md`. Add a `## Release <new_version>` heading at the end of the file (versions ascend; the newest is last), followed by one `* ` bullet per change. Past entries were generated by the retired `liq` tooling and carry `_**hotfix**_:` markers and author/timestamp suffixes; hand-written entries need only a plain bullet. The `.meta/changelog.yaml` file is a legacy `liq` work log and is not updated by this procedure.

## Build

1. `npm ci`
2. `make all` (equivalently `npm run build`) — rolls `src/cli` into `bin/md2x` and builds `src/node` into `dist/md2x.js`
3. `make qa` — runs the bats and Jest suites plus lint

## Artifacts

- `bin/md2x`
- `dist/md2x.js`

Both are gitignored build outputs; never edit them directly.

## Tag prefix

`v`

## Tag push

`npm version` creates the annotated tag locally. Push the branch and the tag with an explicit refspec:

`git push origin refs/tags/v<new_version>`

Also push the version commit's branch (`git push origin <branch>`). The `postversion` script in `package.json` pushes to a remote named `upstream`, which this repository does not currently configure (only `origin`), so it may fail after the tag is created. Never skip `preversion` (for example with `--ignore-scripts`); if `postversion` fails, push the tag manually as above.

## Registries

| Registry | Publish command |
|---|---|
| npm (`@liquid-labs/md2x`) | `npm publish --tag <dist_tag>` — **user-run** if publish requires an interactive one-time code |

`<dist_tag>` is `alpha` for `1.0.0-alpha.N` versions (npm otherwise would set `latest` on a prerelease). Confirm the tag with the user before publishing.

## Credential pre-flight

`npm whoami` and `gh auth status`. If either fails, ask the user to authenticate in their own terminal (`npm login`, `gh auth login`) and re-run the check.

## Dry run

`npm publish --dry-run --tag <dist_tag>` validates the publish plan without side effects.
